# 多人试用接入方案

核实日期：2026-09-11。状态：方案准备，未开通云环境，未接入真实登录或同步。

## 推荐路线

优先评估腾讯云 CloudBase：身份认证 v2 邮箱验证码、内置邮件代发、数据库、云存储与网站托管。无需购买维护独立服务器。前端沿用现有工作台，现有 Sites 身份与线上旧版不修改；目标环境开通后再实施适配。

纠正之前表述：CloudBase 当前官方文档支持内置邮件代发，因此不必一开始单独开通邮件供应商或配置个人 QQ SMTP。QQ 和 163 是试用者收件地址，能否及时到达收件箱需真实测试，不作送达承诺。

## 用户先完成的最小开通

1. 注册/登录腾讯云并按平台要求完成账号认证。
2. 打开 CloudBase 控制台，创建用于测试的环境。先查看当前可用试用资格、套餐价格和到期规则，不默认购买长期套餐。
3. 在身份认证 → 登录方式 → 邮箱验证码 → 配置发件邮箱中，若当前环境支持，选择开启邮件代发。
4. 仅反馈环境 ID、地域、是否成功开启邮件代发。不要在聊天中发送 SecretKey、邮箱授权码、验证码等秘密。

文档描述可能与账号控制台入口存在差异，遇到限制先核对，不假装已经配置。

## 域名与费用

官方默认域名用于开发测试，有限流与访问提示中间页；不能承诺长期稳定对外试用。正式浏览器访问要求自定义域名，按大陆云环境平台要求处理备案。

CloudBase 环境可作为备案资源，但官方要求个人版及以上、剩余有效期超过6个月、开启云托管固定IP。不要把“无需买独立服务器”说成“备案和长期运行免费”。套餐、域名、固定IP、存储/流量和邮件额度均以用户控制台为准，当前未报价或购买。

## 实施工作范围

- 登录与注册独立入口，共用邮箱验证码验证流程，不经过 ChatGPT 登录。验证码错误、过期、发送间隔、失败与会话失效都有反馈。
- 所有数据与附件绑定经验证的用户身份，后端规则拒绝跨用户访问；不能靠前端 userId 过滤。
- 不再把 localStorage/IndexedDB 当成正式唯一存储。按账号加载云端数据，退出清理显示与缓存，切换账号不继承前一个人的内容。
- 服务端采用版本检查处理并发，避免当前整份 state 的旧快照覆盖新数据。保存失败保留编辑草稿，不伪报成功。
- 新账号从空数据开始；种子示例必须显式选择，不复制当前用户数据。
- 本机旧数据迁移需提供预览并由用户确认账号归属。附件需从原 origin 的 IndexedDB 上传；另一个网址无法自动读取 localhost 的文件库。
- 保留JSON与PDF分别备份，再做迁移。旧预览继续可用，不能用硬切换登录页面阻塞用户查看原数据。
- 上线验证至少两个独立账号：QQ/163 实际收信、注册登录、跨端读写、退出切号、跨用户拒绝访问、附件权限、并发修改与错误恢复。

## 下一步依赖

需要用户开通云环境及可用连接授权，才能配置认证、真实邮件和存储并验收。当前没有环境ID或授权，不能声称多人试用已完成。不为了满足进度造假验证码或仅做本地登录。
